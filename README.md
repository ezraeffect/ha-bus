# TAGO Bus Location (Home Assistant)

국토교통부 TAGO 버스 API로 시내버스의 실시간 위치를 Home Assistant 지도에 표시하는 커스텀 통합입니다.
천안(34010)을 기본값으로 두었지만, TAGO에 등록된 다른 시·군 버스도 쓸 수 있습니다.

- **실시간 버스:** 운행 중인 버스 한 대마다 `geo_location` 엔티티를 만들고, 운행이 끝나면 자동으로 지웁니다.
- **전용 지도 카드:** 실제 도로를 따라 그린 경로선, 정류장, 버스를 함께 보여줍니다. 마우스를 올리면(터치 화면은 탭) 상세 정보가 뜹니다.
- **즐겨찾는 정류장:** 지도에서 정류장을 눌러 노선마다 하나씩 정할 수 있습니다. 오른쪽 위 **도착 개요** 패널과 센서로 도착 예정 시간(분)과 남은 정거장 수를 보여줍니다.
- **운행 대수 센서:** 전체 대수와 방향별 대수를 따로 보여줍니다.
- **호출량 절약:** 운행 중인 버스가 없으면 조회 주기를 5분으로 늘립니다.

## 1. API 키 발급

1. [공공데이터포털](https://www.data.go.kr)에 로그인합니다.
2. 아래 API에 각각 **활용신청**을 합니다. 개발계정은 자동 승인됩니다.

   | API | 필요 여부 |
   |---|---|
   | [국토교통부_(TAGO)_버스위치정보](https://www.data.go.kr/data/15098533/openapi.do) | 필수 |
   | [국토교통부_(TAGO)_버스노선정보](https://www.data.go.kr/data/15098529/openapi.do) | 필수 |
   | [국토교통부_(TAGO)_버스도착정보](https://www.data.go.kr/data/15098530/openapi.do) | 선택: 즐겨찾는 정류장의 도착 예정 시간(분)을 볼 때 |

3. 마이페이지에서 **일반 인증키**를 복사합니다. 세 API 모두 같은 키를 쓰고, Decoding 키와 Encoding 키 중 아무거나 써도 됩니다.

> 발급 직후에는 키가 활성화될 때까지 1~2시간 걸릴 수 있습니다.

## 2. HACS로 설치

1. HACS → 오른쪽 위 ⋮ → **사용자 지정 저장소**를 엽니다.
2. `https://github.com/ezraeffect/ha-bus`를 입력하고 유형은 **Integration**으로 고릅니다.
3. **TAGO Bus Location**을 설치한 뒤 Home Assistant를 재시작합니다.

지도 카드는 통합에 들어 있어서 따로 설치하지 않아도 됩니다. 업데이트 후 카드가 예전 모습이면 브라우저를 강력 새로고침(Ctrl+F5)하세요.

## 3. 설정

**설정 → 기기 및 서비스 → 통합 구성요소 추가 → TAGO Bus Location**

1. 인증키를 입력합니다.
2. 도시로 `천안시 (34010)`를 고르고, 노선 번호에 `5`를 입력합니다.
3. 검색된 노선 목록이 기본으로 모두 선택되어 있습니다. 상행과 하행이 따로 등록된 노선이라면 둘 다 선택된 채로 두면 됩니다.

### 구성 옵션

통합의 **구성** 버튼을 누르면 설정할 수 있습니다.

- **조회 주기:** 기본값은 30초입니다.
- **실제 도로를 따라 경로선 그리기:** 기본으로 켜져 있습니다. 아래 [경로선](#경로선) 설명을 참고하세요.
- **즐겨찾는 정류장:** 노선마다 하나씩 고릅니다. 지도 카드에서 정류장을 눌러 정해도 똑같이 저장됩니다.

### 즐겨찾는 정류장 센서

노선마다 아래 센서 두 개가 항상 만들어집니다. 즐겨찾는 정류장을 바꿔도 엔티티 ID는 그대로라서 자동화를 고칠 필요가 없습니다.

| 센서 | 내용 |
|---|---|
| `즐겨찾기 도착 예정` | 다음 버스까지 남은 시간(분). 속성에 정류장 이름, 두 번째 버스, 저상버스 여부가 들어 있습니다. |
| `즐겨찾기 남은 정거장` | 다음 버스까지 남은 정거장 수 |

- 즐겨찾는 정류장을 정하지 않았으면 두 센서 모두 `알 수 없음`입니다.
- 버스도착정보 API를 신청하지 않았거나 조회에 실패하면 도착 예정 센서는 `알 수 없음`이 되고, 남은 정거장 센서는 버스 위치로 계산한 값을 보여줍니다. 이때 속성의 `source` 값은 `bus_location`입니다.

## 4. 지도 카드

```yaml
type: custom:tago-bus-map-card
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `entry_id` | 전체 | 여러 노선을 추가했을 때 하나만 표시 |
| `height` | 자동 | 지도 높이(px). 비워 두면 패널 보기에서는 화면을 꽉 채우고, 섹션 보기에서는 카드 크기에 맞춥니다. 그 밖의 보기에서는 400px입니다. |
| `show_stops` | `true` | 모든 정류장 표시. `false`로 두면 즐겨찾는 정류장만 표시합니다. |
| `show_route_line` | `true` | 노선 경로선 표시 |
| `show_legend` | `true` | 왼쪽 아래 색상 범례 표시 |
| `show_overview` | `true` | 오른쪽 위 도착 개요 패널 표시 |
| `dark_mode` | `auto` | `auto`, `light`, `dark` 중 하나 |
| `scroll_wheel_zoom` | `true` | 마우스 휠로 확대·축소 |
| `tiles` | `auto` | 배경 지도. 아래 [배경 지도](#배경-지도) 참고 |

### 배경 지도

`tiles: auto`(기본값)이면 아래 순서로 먼저 되는 것을 씁니다. 따로 API 키는 필요 없습니다.

1. **`naver`:** [naver_map_change](https://github.com/Leek13rl45/ha_naver_map_change) 통합이 설치돼 있으면, 그 통합이 HA를 통해 제공하는 네이버 지도 타일을 씁니다. HA 기본 지도와 같은 배경이 되고, 다크 모드도 네이버 다크 지도로 바뀝니다.
2. **`ha`:** HA 2026.9 이상에 있는 코어 `map_tiles` 프록시로 OpenStreetMap 타일을 받습니다.
3. **`osm`:** 그보다 오래된 HA면 OpenStreetMap 타일 서버에서 직접 받습니다.

특정 배경을 강제로 쓰려면 `tiles`에 `naver`, `ha`, `osm` 중 하나를 넣으세요. 고른 배경을 쓸 수 없으면 다음 순서로 넘어갑니다.

### 도착 개요 패널

- 오른쪽 위에 있고, 제목을 누르면 열리고 닫힙니다. 열림·닫힘 상태는 브라우저에 저장됩니다.
- 노선마다 즐겨찾는 정류장까지 이번 버스와 다음 버스가 **몇 분, 몇 정거장** 남았는지 보여줍니다.
- 첫 줄에 노선 번호, 다음 줄에 정류장과 방향이 나옵니다. 칸보다 긴 글자는 좌우로 천천히 흘러가며 보입니다.
- 즐겨찾는 정류장이 없는 노선은 설정 안내 문구만 나옵니다.
- 항목을 누르면 지도가 그 정류장으로 이동합니다.

### 색상과 범례

- **노선이 하나일 때:** 방향마다 색이 다르고, 범례에 노선 번호와 방향이 나옵니다.
- **노선이 여러 개일 때:** 노선마다 색이 다르고, 같은 노선의 상행·하행은 같은 색입니다. 범례에도 노선 번호만 나옵니다.
- 방향은 경로선 위의 작은 화살표로 구분합니다.

### 조작

- **버스에 마우스를 올리면:** 차량번호, 방향, 현재·다음 정류장, 즐겨찾는 정류장까지 남은 정거장, 집까지 거리, 위치 갱신 시각
- **버스를 클릭하면:** 엔티티 상세 창이 열립니다.
- **정류장에 마우스를 올리면:** 정류장 이름, 순번, 방향, 다가오는 버스
- **정류장을 누르면:** 같은 정보와 함께 **★ 즐겨찾는 정류장으로 설정** 버튼이 뜹니다. 이미 즐겨찾기가 있는 노선이면 새 정류장으로 바뀝니다. 즐겨찾는 정류장은 ★로 표시되고, 다시 누르면 해제할 수 있습니다.

### 경로선

TAGO는 정류장 좌표만 주기 때문에, 정류장을 순서대로 [OSRM](https://project-osrm.org) 공개 경로 서버(OpenStreetMap 도로망)에 보내 실제 도로를 따라가는 경로를 받아옵니다. 경로선은 반투명 벡터 선으로 그리고, 선 위에 진행 방향을 가리키는 작은 화살표를 일정 간격으로 넣습니다.

- 노선 모양이 바뀔 때만 조회하고, 결과는 HA의 `.storage`에 저장해 둡니다.
- 조회에 실패하거나 경로가 너무 크게 돌아가면(잘못 붙은 정류장) 그 구간만 직선으로 그립니다.
- 처음 설치할 때는 잠깐 직선으로 보이다가 계산이 끝나면 도로 경로로 바뀝니다.
- OSRM은 일반 도로 기준으로 경로를 계산해서, 버스 전용 차로나 회차 구간은 실제 운행 경로와 조금 다를 수 있습니다.
- 외부 서버로 좌표를 보내고 싶지 않으면 구성에서 끄세요. 끄면 직선으로 그립니다.

지도 라이브러리 [Leaflet](https://leafletjs.com)은 cdnjs에서 불러옵니다. 그래서 대시보드를 여는 기기가 인터넷에 연결되어 있어야 합니다.

### 지도 전용 대시보드

지도를 크게 보려면 대시보드 보기(view)를 **패널** 유형으로 만들고 이 카드 하나만 넣으세요. `height`를 비워 두면 화면 크기에 맞춰 꽉 찹니다.

```yaml
views:
  - title: 버스
    path: bus
    type: panel
    cards:
      - type: custom:tago-bus-map-card
```

### HA 기본 지도에 표시할 엔티티

HA의 지도 대시보드와 지도 카드는 위치 정보가 있는 엔티티를 모두 표시합니다. 전용 카드만 쓴다면 기본 지도가 복잡해지지 않게 통합의 **구성 → HA 기본 지도에 표시할 엔티티**에서 고르세요.

| 항목 | 기본값 | 선택하지 않으면 |
|---|---|---|
| 운행 중인 버스 | 표시 | HA 지도에서 빠집니다. 전용 카드에는 그대로 나오지만, `geo_location` 영역(zone) 트리거는 동작하지 않습니다. |
| 즐겨찾는 정류장 센서 | 숨김 | 센서의 좌표 속성 이름이 `stop_latitude`, `stop_longitude`로 바뀌어 HA 지도에서 빠집니다. |

즐겨찾기·운행 대수 센서 같은 일반 엔티티는 엔티티 설정에서 하나씩 **숨김** 처리해도 HA 지도에서 빠집니다. 버스 엔티티는 운행에 따라 생겼다 사라지기 때문에 위 옵션으로만 조절할 수 있습니다.

HA 기본 지도 카드로 버스만 볼 수도 있습니다. 이때는 위 옵션에서 "운행 중인 버스"를 켜 두세요.

```yaml
type: map
geo_location_sources:
  - tago_bus
```

## 자동화 예시

### 버스가 즐겨찾는 정류장 3정거장 전이면 알림

```yaml
triggers:
  - trigger: numeric_state
    entity_id: sensor.<즐겨찾기_남은_정거장_센서>
    below: 4
actions:
  - action: notify.notify
    data:
      message: >
        5번 버스가 {{ state_attr(trigger.entity_id, 'favorite_stop') }}
        {{ states(trigger.entity_id) }}정거장 전입니다.
```

`<...>` 부분은 **설정 → 엔티티**에서 실제 엔티티 ID를 찾아 바꾸세요.

### 버스가 zone에 들어오면 알림

```yaml
triggers:
  - trigger: geo_location
    source: tago_bus
    zone: zone.bus_stop
    event: enter
actions:
  - action: notify.notify
    data:
      message: "{{ trigger.to_state.attributes.vehicle_no }} 버스가 근처에 왔습니다."
```

## 호출량 참고

일일 한도는 API마다 따로 적용됩니다. 아래는 24시간 내내 같은 주기로 조회한다고 가정한 값이고, 밤에는 5분 간격으로 늦춰지므로 실제 호출은 더 적습니다.

- **버스위치정보:** 조회할 때마다 선택한 노선 수만큼 호출합니다. 노선 2개를 30초 간격으로 조회하면 하루 약 5,760회입니다.
- **버스도착정보:** 조회할 때마다 즐겨찾는 정류장 수만큼 호출합니다. 정류장 2개를 30초 간격으로 조회하면 하루 약 5,760회입니다.
- **버스노선정보:** 시작할 때와 하루 한 번만 호출합니다.
- **OSRM 경로:** 노선 모양이 처음 보이거나 바뀔 때만, 1초 간격으로 몇 번 호출합니다.

## 문제 해결

### 로그에 `가용한 세션이 존재하지 않습니다. (30/30)`

공공데이터포털이 인증키당 동시 접속 수를 제한해서 돌려주는 응답입니다. 통합은 이 오류를 일시적인 것으로 보고 1초, 3초 뒤 다시 시도하며, 요청도 한 번에 하나씩만 보냅니다. 그래도 자주 보이면 아래를 확인하세요.

- 구성에서 **조회 주기**를 늘립니다(예: 30초 → 60초).
- 같은 인증키를 다른 프로그램에서도 쓰고 있다면 나눠 쓰거나 키를 따로 발급하세요.
- 계속 실패해도 지도의 버스는 마지막 위치를 유지하고, 다음 조회에서 복구됩니다.

### 로그에 `Entity id already exists - ignoring: geo_location.tago_bus_...`

버스가 API 응답에서 잠깐 빠졌다가 다시 나타날 때, 엔티티를 지우는 도중에 같은 버스가 다시 들어와서 생기던 문제입니다. 지금은 응답에서 사라진 버스를 **3분간 그대로 두었다가** 지웁니다. 잠깐 끊긴 버스는 지도에서 사라지지 않고, 이 오류도 나오지 않습니다.

### 대시보드에 "구성 오류"가 뜨고 콘솔에 `Cannot read properties of undefined`

카드가 지도를 준비하는 동안 HA가 상태를 갱신하면 그리기 코드가 먼저 실행돼 나던 오류입니다. 0.5.1에서 준비가 끝난 뒤에만 그리도록 고쳤습니다. 업데이트 후에도 보이면 브라우저를 강력 새로고침(Ctrl+F5)해서 예전 카드 파일이 캐시에 남아 있지 않은지 확인하세요.
